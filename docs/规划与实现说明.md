# 数独乐园 · 产品规划与实现说明

给家里小朋友练脑用的原生 Android 数独小游戏。本文件记录**已完成的范围**和**后续可以怎么迭代**。

---

## 1. 产品定位

| 项目 | 说明 |
| --- | --- |
| 目标用户 | 5～12 岁，从没玩过数独的小朋友也能上手 |
| 使用场景 | 家里碎片时间，一局 2～20 分钟 |
| 核心目标 | 让孩子**愿意主动打开**，且**不会因为太难而放弃** |
| 设计原则 | 无广告、无内购、无需联网、不收集任何数据 |

给孩子做数独，难点不是规则，而是**「卡住就放弃」**。所以设计重点放在降低挫败感上：难度从 4×4 起步、失误不算输、随时暂停存档、通关一定给星星。

---

## 2. 三种盘面 · 四档难度

### 盘面尺寸（这是本次新增的核心）

| 盘面 | 宫格 | 数字范围 | 适合 | 单局时长 |
| --- | --- | --- | --- | --- |
| 🐣 **4×4** | 2×2 宫 | 1–4 | 完全没玩过，5～7 岁 | 1～3 分钟 |
| 🐥 **6×6** | 2×3 宫 | 1–6 | 已经会玩 4×4 | 3～8 分钟 |
| 🦉 **9×9** | 3×3 宫 | 1–9 | 标准数独 | 8～20 分钟 |

**默认进入 4×4**，孩子第一次打开就能立刻做出来。熟练后自己切到 6×6、9×9。

> 6×6 用的是 2 行 × 3 列的宫，这是儿童数独的标准做法，比 3×2 更好数。

### 难度

同一盘面下，**留的提示数字越少越难**。所有题目都保证唯一解。

| 难度 | 4×4 | 6×6 | 9×9 |
| --- | --- | --- | --- |
| 🌱 轻松 | 留 9 个 | 留 20 个 | 留 46 个 |
| 🌿 进阶 | 留 8 个 | 留 17 个 | 留 38 个 |
| 🔥 挑战 | 留 7 个 | 留 14 个 | 留 31 个 |
| 🏆 大师 | 留 6 个 | 留 12 个 | 留 26 个 |

实测 12 种组合（3 盘面 × 4 难度）**全部精确达到目标提示数**，难度不会倒挂。

### 游戏内功能

- **全局高亮**：选中一格时同行、同列、同宫一起变浅色，帮孩子建立「行/列/宫」概念
- **同数字高亮**：场上相同数字一起标黄，方便排除法
- **笔记模式**：格内小字记候选数，格子形状跟着盘面变（4×4 是 2×2、6×6 是 2×3、9×9 是 3×3）
- **填错立刻标红**，不让孩子在错误前提上继续推理
- **自动清理笔记**：填入正确数字后，同行列宫的候选数自动去掉
- **撤销**：最多回退 100 步
- **分层提示**：4×4 每局 2 次，6×6 / 9×9 每局 3 次；每次提示分三步（详见 3.6）
- **计时 + 暂停**：暂停自动存档，切后台也会暂停
- **重玩本局**：题目不变，重新开始
- **自动存档**：每 5 秒存一次，退出 App 也不丢进度，切盘面/难度后仍能回到原局

### 首页

像闯关地图一样分成两步：**① 选盘面 → ② 选难度**。

- 三张盘面卡片，显示该盘面当前难度下的最佳成绩
- 四张难度卡片，直接写明「留存 N 个数字」，家长一看就懂
- 累计通关局数与星星数，表情随进度解锁（🌱 → 🌿 → 🌳 → 🏆）
- 有未完成的对局时出现「继续上一局」卡片

### 排行榜

每个「盘面 × 难度」组合各有一份**前十名**榜单（共 12 份，互不干扰）。4×4 的 30 秒和 9×9 的 30 秒不能比，所以必须分开。

- 首页右上角「🏆 排行榜」进入
- 顶部两排标签切换盘面与难度，切换不影响下一局的选择
- 前三名有 🥇🥈🥉 奖牌，其余显示数字名次
- 每行显示：用时、失误、提示、日期、星级
- 空榜时提示「通关一局就会出现在这里」
- **通关弹窗直接告诉你名次**：「🏆 新纪录！登上了第 1 名」/「🎖️ 进入排行榜第 3 名」；没进前十就不显示，不打击孩子
- 通关弹窗新增「🏆 看看排行榜」按钮，点击后弹窗立即关闭并跳到榜单

排序规则：**用时越短越靠前**；用时相同时，先玩的那局保留更好名次（避免每次启动顺序乱跳）。只保留前 10 条，更慢的成绩直接丢弃。

### 通关结算

- 星级：**0 失误 0 提示 = 3 星**，失误 + 提示 ≤ 3 = 2 星，其余 1 星
- 显示盘面、难度、用时、失误、提示
- 破纪录标「🏅 新纪录」
- 一键「再来一局」或「回到首页」

## 3. 技术实现

| 项目 | 选择 |
| --- | --- |
| 语言 | Kotlin 2.2.20 |
| UI | Jetpack Compose + Material 3（支持深色模式） |
| 架构 | 单 Activity + ViewModel + StateFlow 单向数据流 |
| 最低版本 | Android 8.0（API 26），目标 API 36 |
| 存储 | SharedPreferences + JSON |
| 出题 | 自研位运算回溯求解器 |
| 依赖 | 无网络库、无第三方 SDK |

### 关键设计：一套代码支持三种盘面

盘面尺寸不是写死成 9，而是抽象成一个 `BoardSpec`（行数、宫的行数、宫的列数）：

```kotlin
BoardSpec.FOUR = BoardSpec(size = 4, boxRows = 2, boxCols = 2)
BoardSpec.SIX  = BoardSpec(size = 6, boxRows = 2, boxCols = 3)
BoardSpec.NINE = BoardSpec(size = 9, boxRows = 3, boxCols = 3)
```

求解器、出题器、棋盘绘制、笔记小格、数字键盘全部从它推导，所以**加一种新盘面只要加一行**。

### 出题算法

1. 回溯法生成完整终盘（候选数随机排序，每局不同）
2. 按**中心对称**成对挖空，每挖一次都用求解器验证「解是否仍然唯一」，不唯一就填回去
3. 对称挖不到目标时，再单格补挖
4. 求解器用**位掩码 + 最少候选优先**

关键点：**每挖一格都验证唯一解**。很多简单实现只生成终盘然后随便挖，会出现多解题目 —— 孩子填出一个「说得通」的答案却被判错，这是最伤兴趣的体验。

生成一次会出 8 个候选盘，取**提示数最接近目标**的那个。没有这一步，4×4 上会出现「大师比挑战还简单」的倒挂（实测确实发生过，已修）。

出题耗时（连续 3 次）：4×4 约 1ms、6×6 约 2ms、9×9 约 6ms，手机上无感。

## 3.5 声音与提示

### 音效与震动

用系统 API 现场合成波形，**不打包任何音频文件**，因此安装包体积没有增加。

| 时机 | 声音 | 震动 |
| --- | --- | --- |
| 填对 | 上行两音（A5→D6），-8 dBFS | 极轻 18ms |
| 填错 | 下行两音（Eb4→Bb3），低而软，-10.5 dBFS | 两下短震 |
| 通关 | 大三和弦琶音 C-E-G-C，-6.7 dBFS | 三连轻震 |
| 擦除 | 单音极短提示，-11.1 dBFS | 12ms |

音量按用途区分：填错听得最多，所以最轻；通关可以最响。全部低于 -6 dBFS，在手机外放上清晰但不刺耳。

右上角一个 🔇/🔊 开关同时关掉声音和震动——真实场景是「哄睡时孩子在旁边玩」，两者应该一起停，做成两个开关只会多一个没人管的设置。开关状态会记住。

### 错题提示说人话

填错时不再只是变红，而是告诉孩子为什么：

- 「这一行已经有 3 了哦」
- 「这一列已经有 5 了哦」
- 「这一宫已经有 2 了哦」
- 若没有直接冲突：「这一格还不能填 8，再看看别的线索～」

同时**棋盘上把造成冲突的格子标成琥珀色并描边**，提示条也用同一套琥珀配色，两者读起来是同一件事，而不是两条无关信息。提示 3.2 秒后自动消失，换格子、填对、撤销、擦除时立即清除。

提示条占用的高度是**固定**的，所以它出现和消失时棋盘不会移动——这点有专门测试守着，否则孩子瞄准格子时提示一弹，手指就会点到别的格子上。

## 3.6 分层提示

原来的提示直接填答案，孩子卡住时得到的只是结果，学不到方法。现在一次提示分三步：

| 步骤 | 内容 | 消耗提示次数 |
| --- | --- | --- |
| ① 引导 | 「试试看：这一行里，哪个数字只剩一个位置了？」 | **不消耗** |
| ② 聚焦 | 高亮目标格，「看这一行，有哪个数字只能填在这里？」 | **不消耗** |
| ③ 揭晓 | 高亮并把数字填进去 | 消耗 1 次 |

**只有第三步才扣提示次数**。前两步是在教方法，如果也要扣次数，孩子会因为「想知道怎么想」而被惩罚，反而更不敢用提示。

技术上用一个 `HintPlanner` 找出当前最容易解释的技巧：先看单候选格（naked single），再看某个数字在行/列/宫是否只剩一个位置（hidden single）。两者都是初学者最先该掌握的方法。

iOS 端有同样的实现，共用同一套规则。

## 5. 后续迭代建议

### 第一阶段：体验打磨（半天～1 天）

- **音效与震动**：填对轻响、填错轻震（系统 `HapticFeedback`，无需素材）
- **过关动画**：星星弹出已有基础，可加撒花
- **每日一题**：按日期做种子，全家玩同一道题比快

### 第二阶段：成长性（2～3 天）

- **本地多小朋友档案**：家里两个孩子各自独立进度（很实际的需求）
- **成就系统**：连续 7 天、首次 3 星、三盘面全通……
- **教学引导**：第一次玩时用箭头动画演示「这一宫已经有 1、2、3 了，所以只能填 4」

### 第三阶段：题目更精细（3～5 天）

当前难度只用**提示数**衡量，简单可靠但不够精细。更专业的做法是按**解题技巧**分级：

- 实现「唯一候选数 / 隐性唯一数 / 数对 / 区块排除」检测
- 按「解开它至少需要哪种技巧」重新分级，这样 31 个提示但全是唯一候选的题不会冒充高难度

### 技术侧待办

- 用真机或 Gradle Managed Device 跑一次 UI 冒烟测试（本次受环境限制未做）
- 为 4×4 增加更细的难度档（现在四档之间只差 1 个提示数）

## 6. 安装包体积

| 包 | 体积 | 说明 |
| --- | --- | --- |
| `app-release-signed.apk` | **1.0 MB** | 日常安装用这个 |
| `app-debug.apk` | 11 MB | 开发调试用，带 Compose 调试工具且不做压缩 |

最初装出来是 17MB，排查后有三层原因：

1. **`material-icons-extended` 是主因**。这个库把 5000 多个 Material 图标全部编译成 Kotlin 代码，dex 里有 **46300 个图标类引用**，而 App 实际只用了 7 个图标。已移除，改成在 `ui/icons/SudokuIcons.kt` 里本地定义，路径数据直接取自原始 Material 图标（逐像素比对确认外观完全一致）。
2. **debug 构建不做代码压缩**，dex 达 57MB（压缩后 17MB）。
3. **release 没开 R8**。

修复后：
- debug：17MB → 11MB（去掉图标库）
- release：开启 R8 + 资源压缩 → **1.0 MB**

release 包已用 debug 密钥签名，可以直接装到手机。如果要上架应用商店，需要换成正式签名密钥。

> R8 会把类名混淆，所以专门验证了两件容易被打包搞坏的事：`GameViewModel` 的 `(Application)` 构造函数仍然保留（`viewModel()` 是靠反射创建它的），父类仍是 `AndroidViewModel`。

## 7. 怎么运行

```bash
./gradlew installDebug      # 装到设备（调试版）
./gradlew installRelease    # 装到设备（正式版，体积小）
./gradlew assembleRelease   # 打包，产物在 app/build/outputs/apk/release/
./gradlew testDebugUnitTest
```

安装包里最小的那个在 `app/build/outputs/apk/release/app-release-signed.apk`（1.0 MB）。

或用 Android Studio 直接打开本目录，Gradle 同步后点运行。

> 本机沙箱备注：我构建时用了 `ANDROID_USER_HOME`、`GRADLE_USER_HOME` 指向项目内目录，并加了 `-Pkotlin.compiler.execution.strategy=in-process`。你用 Android Studio 打开时**不需要**这些参数。
